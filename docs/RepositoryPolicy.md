# 本地协作与仓库内容约定

本页及完整 AI／开发日志管理规则进入 `local/` 独立协作仓库，不进入公开引擎仓库。公开仓库保存可独立使用的引擎源码、Shader、必要资源、示例工程、构建配置、测试工具、许可证及技术文档。用户明确允许根 `AGENTS.md` 和 `scripts/Sync-Workspace.ps1` 作为公开轻量调用入口：可说明原运行路径、协作资料位置及安装方式，不复制实际 skills、角色、进度或日志。克隆后的引擎构建与使用不依赖协作资料。具体双仓库流程见 [WorkspaceSync.md](WorkspaceSync.md)。

## 内容归属

2026-10-29 用户明确允许 RestArtEngine_Workspace 改为 Public：本协作库中的规范、skills、agents、进度、经验与底稿可对外公开，已有版本历史也会可见。此前关于该库必须私有的限制由此替代；引擎源码库仍不收录完整协作资料。凭据、机器配置与聊天数据库的排除规则保持不变。

历史记录中的“只保留本地／不提交”若描述协作规范和日志，按当前规则解释为“不进入公开引擎库”；它们可进入独立协作库。凭据、机器配置、聊天数据库与原始大体积证据仍不在本次同步范围。公开入口例外仅限用户授权的通用调用内容。

| 内容 | 处理方式 |
| --- | --- |
| `include/`、`src/`、`app/`、`Shaders/`、`tests/` | 公开维护，引擎接口、实现与测试。 |
| 引擎根 `Content/`、`Projects/`、`assets/` | 公开维护内置共享资产、示例场景、材质、网格及引擎必要资源；引擎 Content 是发行内容，与本地协作资料无关。提交前检查示例改动是否属于本次任务。 |
| CMake / Premake 配置、`scripts/`、`vendor/` | 公开维护构建、验证和依赖说明；保留第三方版本与许可证。 |
| `README.md`、`docs/` 中列入白名单的文档 | 公开维护操作说明、格式、架构、设计约束、平台边界和可复现验证方法。 |
| 通用调用入口 | 根 `AGENTS.md` 与公开同步薄封装可提交引擎库；完整协作内容在独立Workspace库公开，不随入口复制进引擎库。 |
| 项目 AI 角色、技能及完整协作规范 | 协作 `local/` 仓库同步；运行副本仍位于根 `.agents/skills/`、`.codex/agents/`，不进入引擎库。 |
| 开发日志、写作规范、底稿、进度交接、源码阅读笔记 | 作为协作 `local/docs/` 文本同步；历史绝对路径只作证据，不充当新机器配置。 |
| 正式文章、配图／动图、聊天数据库、原始测试证据 | 仓库外或本机忽略目录单独管理，不纳入本次两个Git仓库。 |
| 构建输出、个人 IDE 状态、布局／主题／GC 偏好、测试日志和截图 | 只保留本地；共享 IDE 配置仅保留不含个人路径的少量明确例外。 |
| 凭据、本机环境配置、当前机器路径配置 | 两个仓库都不提交；本机路径放 `local/machine/`，凭据由工具自己的安全配置管理。 |

## 配置保存在哪里

| 配置 | 位置与用途 | 提交／分发规则 |
| --- | --- | --- |
| 共享构建配置 | 引擎根目录的 `CMakeLists.txt`、`CMakePresets.json`、Premake `.lua` 文件 | 可以提交，使用相对路径或环境变量；不写个人 SDK 安装路径。 |
| 个人构建覆盖 | 本地 `CMakeUserPresets.json`、`*.local.*`、环境文件 | 不提交；可公开不含真实凭据和个人路径的 `.env.example`／`.env.sample`。 |
| 引擎身份 | 引擎根目录 `Engine.raeengine` | 可以提交／随发行版提供，标识引擎版本与构建。 |
| 工程配置与资产 | 各工程的 `.raproject`、`Content/`、`Shaders/` | 公开示例可以提交；个人工程单独管理，不自动加入引擎库。 |
| 引擎安装注册表 | Windows 的 `%LOCALAPPDATA%\RAEngine\engines.json` | 本机安装路径映射，不提交、不随工程打包；换机重新登记。 |
| 编辑器偏好 | 默认在进程工作目录的 `RestArtEngine.imgui.ini`、`RestArtEngine.ui.ini`（主题与选中描边；旧 `RestArtEngine.theme.ini` 仅作兼容读取）、`RestArtEngine.gc.json` 等；GC 可通过 `--gc-settings` 指定路径 | 不提交、不当作工程配置；需要迁移时单独处理。 |
| IDE 状态与辅助资源 | 项目的 `.idea/` 等 IDE 目录 | 本机生成物不提交；仅保留忽略规则明确允许的共享配置，不将 IDE 图标混入引擎资源。 |
| 开发协作与写作配置 | 被忽略的本地工作区资料、个人工具配置目录、仓库外内容目录 | 不进入引擎源码仓库或发行包；具体机器路径只记录在本地位置索引。 |

引擎源码根、用户工程根和进程工作目录是不同概念，不能假设编辑器偏好总在源码根。配置内容与解析规则分别见 [工程管理](../../docs/ProjectManagement.md)、[编辑器指南](../../docs/EditorGuide.md) 和 [GC](../../docs/GarbageCollection.md)。

## 文档同步职责

引擎行为、格式或配置发生变化时，更新对应公开领域文档；目录、提交或分发边界变化时，更新本页及 `.gitignore`。本机工作安排、阅读记录、验证历史和写作进度更新各自的本地记录，公开文档不引用这些记录作为使用前提。新增文件先确定归属，再选路径，不能仅因位于 `docs/` 或名为“配置”就认定可以提交。

## 新增文档与资源

协作库 `local/docs/tasks/` 保存任务 README 与 vN 文字日志，`local/docs/experience/` 保存主题经验，具体流程见 [TaskWorkflow.md](TaskWorkflow.md)。协作 `.gitignore` 对这两棵目录仅放行 Markdown；原始日志、截图、二进制证据不随任务文本加入。引擎 `.gitignore` 继续整体忽略 `local/`，不为这些目录开公开例外。

`docs/` 使用 `.gitignore` 中的白名单。新增公开文档时，先确认内容是引擎技术说明且不含 AI、协作过程或项目日志，再同时增加文件和对应忽略例外。领域文档描述当前行为、技术原因、接口约定和限制；日期流水账、某次聊天结论及个人验证产物保存在本地记录中。

公开引擎技术文档只能依赖仓库内已跟踪文件或公开来源。根 `AGENTS.md` 与通用同步薄封装作为例外，可指向可选协作工作区入口，并明确缺失时不影响引擎构建；例外不扩展为公开其他协作正文。源码阅读中提炼出的通用设计说明可以写入领域文档，私人阅读过程和协作提示不随之发布。

保留网格 `.obj` 与引擎图片资源的正常跟踪，不能用全局忽略图片、视频或所有 `.obj` 的方式清理日志。文章素材放在仓库外；临时验证输出使用已忽略的 `artifacts/`、`screenshots/` 等目录，不混入引擎资源。

## 提交检查

```powershell
git status --short
git diff --cached --name-status
git diff --cached --check
git ls-files
git check-ignore -v --no-index -- <待检查路径>
```

使用明确文件路径暂存本次改动，核对暂存区而非只检查工作区。不要强制添加本地协作或写作资料。新增工具和文档时同步检查忽略规则，避免换一种命名后重新进入仓库。

`.gitignore` 只影响未跟踪文件，不能阻止已跟踪文件继续提交。已误跟踪的本地资料需在保留工作区文件的前提下，通过 `git rm --cached -- <明确路径>` 移出索引。删除提交只影响之后的版本，历史提交、远端分支、标签及其他克隆仍可能保留旧内容；历史清理须单独评估所有引用和协作影响，不将忽略规则视为历史擦除。

## 打包与换机

Git 提交、源码归档、运行时发行包、个人备份是不同交付物。`.gitignore` 不过滤手工复制、压缩或上传：不要将包含本地资料的整个工作目录直接打包。源码归档从已检查的提交导出；运行时发行包按 [引擎分发](../../docs/EngineDistribution.md) 的运行文件清单组装，最后检查实际包内文件。忽略的构建产物可以属于运行时发行包，不能因此重新提交进源码库。

公开引擎 clone 不恢复完整技能与进度；另行将协作库 clone 到 `local/` 后，通过 Install 恢复原运行位置，详见 WorkspaceSync。机器偏好、登录凭据和外部文章目录分别处理，不夹带进两个仓库。协作库尚未推送时只有本地版本管理，不代表远端备份完成；旧机器的历史路径不能直接作为新机器配置。
