# v1 — 显式编辑联动与启动配置状态

状态：构建/CTest通过，GPU专项前段通过，新增UI用例未通过；后续见[v2](v2.md)。基线a28f38c，用户Sandbox七项差异不属于本任务。

## 分析

ProjectSettings现有控件仅BeginDisabled，子请求仍勾选，选定不支持光追的后端仍可编辑光追；GI与独立反射/阴影竞争但保留勾选。后端已有下次启动生效说明，却不区分未保存、保存待重启、未保存撤回，以及无效fallback差异。用户明确要求取消应取消的勾选并提示重启。

## 修改与验收设计

新增Editor层纯规则，仅在显式Backend/Hardware/GI method/mode编辑后联动；不在Project IO或设备探测时清理请求。硬件off清光追子开关及GI算法、保留质量/贡献参数；on选择默认反射/阴影；Path Tracing开启硬件并清独立反射，Realtime再清独立光追阴影。非hybrid后端编辑清光追/GI请求，fallback仅native12可编辑。硬件开启清会话analytic竞争项；能力不足只解释原因。

启动策略以真实launch request比较草稿和已保存值，非native12忽略无意义fallback差异；显示SaveAndRestart/Restart/SaveToCancelRestart，不自动关闭程序或热换设备。兼容旧请求在不可用控件中显示未激活及解释，不因仅打开窗口改写文件。

拟验证：ProjectSettingsTests规则与存储事务；既有Hardware RT真实控件套件增加native12/strict/hybrid、保存/重开/撤回、GI依赖、analytic互斥、窄窗双主题和输入隔离；检查实际截图。所有GPU用HEAD Sandbox隔离副本和独立布局。原始证据放artifacts/project-settings-links/v1。
