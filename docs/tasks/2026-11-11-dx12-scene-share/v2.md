# v2 — HDR 与 Bloom 共享，Tonemap 迁到 DX12

状态：通过（实验开关 `--dx12-post`）
基线：`ae36449`（显示色 FXAA）+ 本轮工作区改动；Windows DX11 + DX12；Debug x64
前一版：[v1](v1.md)

## 分析

v1 只共享显示色，Tonemap 仍在 DX11。要让 DX12 真正消费场景 HDR，需要共享 HDR 与 Bloom，并把 Tonemap 的管线与常量搬到 DX12；否则 DX12 只能做显示空间的后处理。

## 修改与验证

### 修改

- `ensureDx12Post` 扩展为 `(sceneW, sceneH, bloomW, bloomH)`，尺寸变化时重建。
- 新增共享 RGBA16F HDR 与 Bloom 纹理（SRV、`NTHANDLE | KEYEDMUTEX`），DX12 打开为 `Rgba16Float`；Bloom 关闭时 Tonemap 的 t1 复用 HDR。
- DX12 Tonemap 管线：`Tonemap.hlsl`、`sourceCount=2`、`b0=sizeof(RhiTonemapConstants)`（112 B）。
- Tonemap Pass：DX12 优先。先把 HDR（和 Bloom）拷入共享输入 → 等待 DX11 GPU → DX12 `drawPostProcess2` → 把共享输出拷到 `SceneColorPost`（后续还有 TAA/运动模糊/FXAA）或显示目标。
- FXAA Pass 继续走 DX12，复用 v1 的显示色共享。
- 任一步失败打印一次原因并回退 DX11 RHI / 原生路径。

## 结论

- HDR、Bloom、显示色三段共享已打通，Tonemap 与 FXAA 在 DX12 上产生与 DX11 路径一致的画面。
- 限制：深度与 TAA 历史未共享，TAA/运动模糊/DOF 仍在 DX11 RHI；同步是 CPU 串行；实验开关默认关闭。
- 下一步：共享深度（需要处理 typeless 深度与 SRV 格式）与 TAA 历史，用共享 fence 替换 CPU 等待，再把 TAA/DOF 迁到 DX12。
