# DX12 共享场景纹理后处理：从一条 Pass 到完整链路

> 学习笔记，对应实现：`--dx12-post`（引擎 `8ce733e` 之后的完整链路）。目标不是背 API，而是理解“两个设备如何安全地共同处理一帧”。

## 1. 为什么需要它

引擎的编辑器、光栅化、资源管理都在 DX11；硬件光追在 DX12/DXR。后处理如果一直留在 DX11，DX12 只能做光追，无法验证 RHI 的跨 API 能力。

`--dx12-post` 把**场景后处理**搬到 DX12：

```text
DX11：场景渲染（HDR/深度/G-Buffer/光照）→ 写共享输入
DX12：Tonemap / TAA / 运动模糊 / 景深 / FXAA
DX11：接收结果 → 编辑器合成 → Present
```

它不是“把整个引擎换成 DX12”，而是**用共享纹理和 fence 把两个设备串成一条流水线**。这也正是跨 API 渲染最核心的问题：资源怎么共享、状态怎么同步、结果怎么回拷。

## 2. 总体架构

```text
                DX11 device                             DX12 device
        ┌──────────────────────┐              ┌──────────────────────┐
场景 ──▶│ SceneColor (RGBA16F) │──copy───────▶│ shared HDR (RGBA16F) │
        │ Depth      (R32)     │──copy───────▶│ shared depth (R32)   │
        │ TAA history(RGBA8)   │──copy───────▶│ shared history       │
        └──────────┬───────────┘              └──────────┬───────────┘
                   │ Signal(fence)                       │ Wait(fence)
                   │                                      ▼
                   │                          ┌──────────────────────┐
                   │                          │ Tonemap/TAA/Motion/  │
                   │                          │ DOF/FXAA pipelines   │
                   │                          └──────────┬───────────┘
                   │                                      │ Signal(fence)
                   ▼ Wait(fence)                          ▼
        ┌──────────────────────┐              ┌──────────────────────┐
        │ 回拷 post/显示/HDR   │◀──copy───────│ shared output        │
        └──────────────────────┘              └──────────────────────┘
```

关键点：**每一段都是“DX11 拷入 → fence → DX12 画 → fence → DX11 拷回”**。不是两个设备同时读写同一张纹理。

## 3. 资源清单

| 资源 | 格式 | DX11 标志 | DX12 用法 |
| --- | --- | --- | --- |
| 显示色输入/输出 | RGBA8 | NTHANDLE + KEYEDMUTEX，RT+SRV | FXAA/TAA 输入、Tonemap/TAA/运动模糊输出 |
| 场景 HDR | RGBA16F | 同上，SRV | Tonemap t0、景深输入 |
| Bloom | RGBA16F | 同上，SRV | Tonemap t1（关闭时复用 HDR） |
| 场景深度 | R32_TYPELESS | 同上，SRV-only | TAA/运动模糊/景深 t1，DX12 SRV 用 R32_FLOAT |
| TAA 历史 | RGBA8 | 同上，SRV-only | TAA t2 |
| HDR 输出 | RGBA16F | RT+SRV | 景深渲染目标，回拷场景 HDR |

常量缓冲契约（由 `RhiPipelineDesc` 反射校验）：

| Pass | 源数量 | b0 字节 |
| --- | --- | --- |
| FXAA | 1 | 16 |
| Tonemap | 2 | 112 |
| TAA | 3 | 208 |
| 运动模糊 | 2 | 176 |
| 景深 | 2 | 48 |

## 4. 一帧的时序

以启用 TAA + FXAA 为例：

1. DX11 渲染场景，得到 HDR、深度。
2. **Tonemap**：DX11 拷 HDR/Bloom 到共享输入 → `Signal(fence, v1)`；DX12 `Wait(fence, v1)` → 画 → `Signal(fence, v2)`；DX11 `Wait(fence, v2)` → 回拷 `SceneColorPost`。
3. **TAA**：DX11 拷 post/深度/历史 → fence 交接 → DX12 画 → 回拷 TAA 写目标与显示目标，翻转历史索引。
4. **FXAA**：DX11 拷 TAA 结果 → fence 交接 → DX12 画 → 回拷显示目标。
5. DX11 继续编辑器合成并 Present。

如果启用运动模糊或景深，顺序由 `ScenePipeline` 的 Pass 声明决定（DOF 在 Tonemap 前，运动模糊在 TAA 后、FXAA 前）。

## 6. 同步：keyed mutex 与 shared fence

这是两条不同的同步线，别混：

- **keyed mutex** 解决“这块纹理现在归哪个设备用”。DX11 每次写共享纹理前后都要 `AcquireSync(0)` / `ReleaseSync(0)`；
- **shared fence** 解决“GPU 完成到哪一步了”。DX11 写完 `Signal`，DX12 队列 `Wait`；DX12 画完反向再来一次。

为什么不能只用 keyed mutex？因为它只保护 CPU 侧的访问窗口，不表达 GPU 队列之间的先后；为什么不能只用 fence？因为 DX11 写共享纹理本身需要 keyed mutex 才能通过校验。

实现上 DX11 用 `ID3D11Device5::CreateFence(..., D3D11_FENCE_FLAG_SHARED, ...)` 导出 NT 句柄，DX12 `OpenSharedHandle` 拿到 `ID3D12Fence`，在命令队列上 `Wait/Signal`。导出的句柄在打开后要 `CloseHandle`。

## 7. 五个容易踩的坑

### 7.1 共享纹理只设 `SHARED_NTHANDLE`

现象：`CreateTexture2D` 返回 `E_INVALIDARG`（0x80070057）。

原因：D3D11 的 NT 句柄共享需要同时带 `SHARED_KEYEDMUTEX`。

### 7.2 共享纹理作为 DX12 渲染目标却没有 RTV

现象：`OMSetRenderTargets: descriptor has not been initialized`，随后 `DrawInstanced: render target format does not match PSO`。

原因：`createTextureFromSharedHandle` 只打开了资源，没有建 RTV 描述符；`createTexture` 路径建了，共享路径漏了。

修复：在 RHI 打开共享纹理时，若 `description.renderTarget` 为真就创建 RTV。

### 7.3 `CopyResource` 前没有解绑

现象：D3D11 validation 报“资源仍绑定”。

原因：上一 Pass 的 RTV/SRV 还绑着源或目标。修复：复制前 `OMSetRenderTargets(1, {nullptr}, nullptr)` 和 `PSSetShaderResources(0, n, {nullptr...})`。

### 7.4 typeless 深度不能直接建 SRV

现象：DX12 采样深度失败或 validation 报错。

原因：共享深度是 `R32_TYPELESS`，typeless 资源建 SRV 必须显式格式。修复：RHI 的 `TextureEntry` 记 `srvFormat`，深度用 `R32_FLOAT`。

### 7.5 以为 fence 能让两个设备并行

现象：加了 fence，帧时间没明显变化。

原因：DX12 RHI 的 `drawPostProcess*` 内部仍 `waitForGpu` 同步等待，整条链仍是串行提交。fence 目前解决的是**正确性与去轮询**，真正并行需要异步 RHI 提交（记录命令、延迟回读）。

## 8. 怎么验证

```powershell
# 构建
& 'C:\Program Files\Microsoft Visual Studio\2022\Professional\MSBuild\Current\Bin\MSBuild.exe' `
  RestArtEngine.sln /m /p:Configuration=Debug /p:Platform=x64 /v:minimal /nologo

# 默认路径（DX11）与 DX12 共享路径各跑 60 帧
bin\windows-x86_64\Debug\RestArtEngine.exe --project Projects\Sandbox\Sandbox.raproject --no-ui --frames 60 --capture-dir artifacts\base
bin\windows-x86_64\Debug\RestArtEngine.exe --project Projects\Sandbox\Sandbox.raproject --dx12-post --no-ui --frames 60 --capture-dir artifacts\dx12
```

判据：

- 两条命令都打印 `validation errors: 0`；
- 截图逐像素比较 MAE 应在 1e-7 量级、最大差 1（同一 shader 的量化差）；
- 开启 TAA 时 MAE 约 8e-5、最大差 15，属于抖动采样差，changed>3 应为 0%；
- 开启运动模糊/景深时 MAE 约 1e-7 / 3e-7。

自动验证：

## 9. 边界与下一步

- 运动模糊、景深、TAA、Tonemap、FXAA 已在 DX12 执行；但每帧多次全屏拷贝，开销明显。
- DX12 RHI 仍是同步提交；下一步是异步命令列表 + 双缓冲回读，fence 才能真正带来并行。
- `--dx12-post` 仍是实验开关，默认关闭，未接项目设置。
- 共享纹理目前是“每帧拷贝”而不是“直接共享原资源”；直接共享需要把场景目标本身建成共享资源，并处理整帧的 keyed mutex。

## 10. 练习建议

1. 把 `ScenePipeline.cpp` 里 FXAA 的 `source` 改成 `SceneColorPost`，观察 `--dx12-post` 画面与验证结果，理解 Pass 声明与执行的关系。
2. 临时把某个 `createPipeline` 的 `sourceCount` 改错，观察反射校验在创建阶段报错，而不是运行时黑屏。
3. 注释掉一次 `AcquireSync`，看 D3D11 validation 如何报错，再恢复。
4. 把 `syncToDx12` 改回 query 轮询，测帧时间差异，理解“正确但不等效”的同步。
5. 给共享资源加一张新纹理（例如 SSAO 结果），按“创建→打开→拷入→绑定→回拷”的顺序接一个 Pass。
