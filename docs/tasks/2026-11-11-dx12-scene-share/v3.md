# v3 — 深度与 TAA 历史共享、共享 fence

状态：通过（实验开关 `--dx12-post`）
基线：`584a977`（HDR/Bloom 共享）+ 本轮工作区改动；Windows DX11 + DX12；Debug x64
前一版：[v2](v2.md)

## 分析

v2 已共享 HDR、Bloom 与显示色，Tonemap/FXAA 在 DX12 执行。TAA 还消费当前帧颜色、深度与上一帧历史：深度是 typeless 资源，不能直接建 SRV；历史需要每帧从上一份写目标拷贝。同步方面，query 轮询只能等 GPU，不能给两个设备建立明确的内存可见性顺序，需要共享 fence。

## 修改与验证

### 修改

- `RenderBackend`：
  - DX12 `TextureEntry` 增加 `srvFormat`，让 typeless 共享深度以 `R32_FLOAT` 建 SRV；
  - `IRenderBackend` 新增 `createSharedFence` / `openSharedFence` / `signalFence` / `waitFence`；DX11 用 `ID3D11Fence`（`D3D11_FENCE_FLAG_SHARED`）导出句柄，DX12 `OpenSharedHandle` 后用队列 `Signal` / `Wait`；Base 后端返回不支持。
- `BackendSmoke`：新增“DX11 与 DX12 共享 fence”用例（建 fence → 打开 → 双向 signal/wait）。
- `SceneRenderer`：
  - 共享深度（`R32_TYPELESS`，每帧从场景深度拷贝）与 TAA 历史（RGBA8）；
  - DX12 TAA 管线：`Taa.hlsl`、3 源（颜色/深度/历史）、`b0=sizeof(RhiTaaConstants)`（208 B）；
  - TAA Pass 在 DX12 执行时回拷到 TAA 写目标与显示目标，并同步更新写索引、历史有效位与上一帧投影；
  - 等待改为共享 fence：DX11 写完后 `Signal`、DX12 `Wait` 再画；画完 DX12 `Signal`、DX11 `Wait` 再回拷。fence 不可用时回退 query 等待。

### 失败与修复

- 第一次比较 TAA 画面时用了目录里较早的 capture（硬件光追那次），与新的 baseline 不可比；改为按文件名显式比较后，DX12 TAA 与 DX11 RHI TAA 基本一致。
- 共享深度直接以 `R32_FLOAT` 打开会丢失 typeless 语义；改为共享 `R32_TYPELESS` + SRV 格式覆盖。
- fence 建在 DX11 侧、DX12 打开后必须 `CloseHandle` 导出的 NT 句柄；打开失败路径也要关。

## 结论

- Tonemap、TAA、FXAA 均可在 DX12 上消费共享场景纹理；TAA 的深度与历史共享已验证与 DX11 RHI 路径一致。
- 限制：运动模糊与景深仍在 DX11；共享输入每帧多一次全屏拷贝；DX12 RHI 的 draw 仍同步等待自身 fence，因此提交仍是串行的，只是不再 CPU 轮询。
- 下一步：把运动模糊/DOF 也接入 DX12，评估异步 RHI 提交（让 fence 真正并行），再决定是否默认启用或接入项目设置。
