# v6 — 异步 RHI 提交（描述符/常量多版本）

状态：通过（实验开关 `--dx12-post`）
基线：`f47f312`（完整后处理链）+ v5 分析；Windows DX11 + DX12；Debug x64
前一版：[v5-async-analysis.md](v5-async-analysis.md)

## 目标

在 v5 的分析基础上落地异步提交：去掉 `executeCommands` 的 CPU 等待，同时保证描述符、常量缓冲和命令对象不会被后续提交覆盖。

## 修改

1. **描述符堆按提交隔离**：每次 `drawPostProcessInternal` 创建自己的 3 槽 shader-visible SRV 堆，随提交对象一起保留到 GPU 完成；不再复用共享的 `srvHeap_`。
2. **常量缓冲 4 槽 ring**：`BufferEntry` 改为 4 个 mapped 槽；`updateBuffer` 轮转，复用前检查该槽最后使用的 fence，必要时等待；draw 使用 `currentSlot` 的 GPU 地址，提交后记录 fence 值。
3. **在飞提交保留**：`InFlightSubmission` 持有 allocator、command list、descriptor heap；`executeCommands` 提交后只 `Signal`，最多 8 个在飞后统一排空。
4. **回读前显式等待**：`readTexture` 在 `Map` 前 `waitForGpu`；`destroyBuffer` / `shutdown` 也先排空。

## 遇到的问题

1. 第一次改完 close command list 报 `E_INVALIDARG`：`SetDescriptorHeaps` 仍引用旧的 `srvHeap_`（此时未创建），改为绑当前提交的 `drawHeap`。
2. 只去掉等待、没有描述符/常量版本化时画面静默错误（v5），这是本轮的直接前提。

## 结论

- DX12 后处理提交已异步：CPU 不再每个 Pass 等待 GPU，最多 8 个提交在飞；共享 fence 继续负责两个设备之间的顺序。
- 限制：每帧仍有多次共享纹理拷贝；异步是“最多 8 个在飞”的有界流水线，不是无限排队；`--dx12-post` 仍为实验开关。
