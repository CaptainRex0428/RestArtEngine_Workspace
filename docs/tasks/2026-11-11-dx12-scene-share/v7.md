## 分析

`--dx12-post` 一直是纯 CLI 实验开关。要让工程真正使用它，需要：工程字段持久化、编辑器可见、CLI 能覆盖，同时保留“设备/着色器不可用时自动回退”。

## 修改

- `Project::RenderingSettings` 新增 `dx12Post`（默认 false），manifest 读写 `rendering.dx12Post`。
- `MinimalApp`：`--dx12-post` / `--no-dx12-post` 改为 `std::optional` 覆盖，优先级高于工程值。
- `ProjectSettings`：Rendering 页新增 **DX12 shared post chain (experimental)** 复选框，实时改 `settings.dx12Post`，并同步进工程草稿参与保存/未保存提示。
- 文档：RenderBackend 阶段 13 的边界、README CLI 表、EditorGuide 的 Project Settings 段落。

## 失败与说明

- `--editor-self-test` 连续两次失败在 native Content 窗口的前台焦点断言；该用例依赖 `SetForegroundWindow`，在当前桌面会话下没有拿到前台。改动只涉及 Project Settings 的一个复选框和工程字段，`--hardware-rt-self-test` 的 Project Settings 保存/重载用例通过，因此暂按环境问题记录，没有归因到本功能。

## 结论

- DX12 共享后处理从 CLI 实验变成工程级选项：默认关闭，工程可持久化，编辑器可切换，CLI 可单次覆盖。
- 限制：仍是实验功能；每帧共享拷贝与有界异步的成本不变；保存路径由编辑器流程覆盖，没有新增专门的工程读写单元测试。
