# v2 — RHI Tonemap 与运行时交换链

状态：通过
基线：引擎 `12cbfd6` 的父提交 `25cf91d`；平台 Windows / DX11；Debug x64
前一版：[v1](v1.md)

## 分析

v1 后 Tonemap 的 RHI 路径在编辑器视口正常，但运行时交换链路径的 Validate 捕获只有天空。排查确认：

- RHI 导入的 HDR 场景纹理与当前 `sceneTexture` 指针一致，viewport/target 正确（1440×900）；
- 运行时路径 `debugView=0`、FXAA 开启，RHI Tonemap 写 `SceneColorPost`；
- 原生 FXAA 消费 RHI 写入的 post 时输出天空；编辑器路径由 RHI FXAA 消费同一 post 则正常。

结论：问题在“RHI post → 原生 FXAA”这一段，而非 HDR 导入或 Tonemap 采样。

## 修改与验证

### 修改

- 运行时 FXAA 也走 RHI：写 `SceneColorDisplay`，再 `CopyResource` 到交换链；移除运行时对原生 FXAA 的依赖。
- 新增 `Shaders/Private/Rhi/Tonemap.hlsl` 与 `RhiTonemapConstants`（112 B），消费 HDR 场景 + Bloom，承载曝光/Bloom/调试视图/viewport/调色/暗角。
- `SceneRenderer` 在 `debugView == 0` 时优先 RHI Tonemap；数据调试视图保留原生 `PSTonemap`，避免直通语义被显示变换改写。
- 导入 HDR 场景与 Bloom 为 RHI SRV，post 升为 RTV 以承接 Tonemap 输出。
- 文档更新 `PostProcessing.md`、`PostProcessingSystem.md`、`HDROutput.md`、`RenderBackend.md`、`RenderingDevelopment.md`。

## 结论与经验

- 运行时交换链不能直接被 RHI 绑定，正确做法是写显示纹理后回拷；这比让原生 FXAA 消费 RHI post 更可控。
- 调试视图是直通语义，和显示变换不同；首版以 `debugView == 0` 为 RHI Tonemap 边界，避免 normals/unlit 被 ACES/gamma 改写。
- Bloom/DOF 仍是 D3D11 多目标 Pass；DX12 仍不能导入场景纹理，整条链迁移未完成。
- 经验并入 [RhiPostProcessing.md](../../experience/RhiPostProcessing.md)。
