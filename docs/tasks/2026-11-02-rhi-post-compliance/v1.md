状态：通过

## 分析

本轮首次把协作库 clone 到 `local/` 并 Install。按 `local/docs/TaskWorkflow.md` 与 `docs/RenderingDevelopment.md` 审计后处理/RHI 设计，确认问题：

1. **阶段契约与实际执行矛盾**：`postProcessStage(PostEffect::Taa)` 返回 `LinearHdr`，但 `SceneRenderer` 的 TAA Pass 位于 tonemap 之后，读取 `SceneColorPost` 并写显示空间历史。阶段枚举是渲染器/编辑器/持久化共享契约，错误会误导后续 Pass 组合与 UI 分组。
2. **Shader 源码入口不合规**：FXAA/Motion/TAA 的 RHI shader 以 `constexpr` 字符串嵌在 `SceneRenderer.cpp`，无法按文件定位，也绕开现有 `reloadShaders` 流程。
3. **重载生命周期缺失**：即使 shader 文件变化，RHI 管线只在首次 `ensureRhi*` 编译，不会在下一次重载时更新。
4. **公开文档过时**：`RenderingDevelopment.md` 仍称“无 TAA”，`PostProcessing.md` 称“TAA 未实现”，`PostProcessingSystem.md` 阶段表把 TAA 放在线性 HDR，测试计数仍为 367/121/727。

## 修改与验证

### 修改

- `src/Renderer/PostProcess.cpp`：`Taa` 阶段改为 `Display`。
- `tests/PostProcessTests.cpp`：阶段断言同步；新增说明 TAA 属显示空间。
- 新增 `Shaders/Private/Rhi/Fxaa.hlsl`、`MotionBlur.hlsl`、`Taa.hlsl`，从 `SceneRenderer.cpp` 原样迁出 shader 源。
- `SceneRenderer::Impl`：三个 `ensureRhi*` 改为 `readText(shaderRoot / "Private/Rhi/...")`；新增 `invalidateRhiPostPipelines()`，在 `applyShaderSource` 成功后释放 RHI post 管线并重置 attempt，下一帧重编译，失败继续 D3D11 回退。
- 公开文档：`PostProcessing.md`、`PostProcessingSystem.md`、`RenderingDevelopment.md`、`RenderBackend.md` 更新 TAA/RHI 状态、阶段表、测试计数与源码位置。

## 结论与经验

- 阶段枚举必须从“实际执行位置 + 色彩空间”推导，不能沿用计划顺序；本轮修正避免 TAA 在 UI/管线层被当作线性 HDR 效果。
- 文件化 shader 是 RHI 后处理可维护的最低要求；重载失效必须成对实现，否则“文件存在”会制造已热编译的假象。
- 仍不满足“整条链迁移”：Tonemap/Bloom/DOF 留在 D3D11，DX12 无场景纹理共享。下一轮先修复 HDR 场景导入身份/生命周期，再迁 Tonemap。
