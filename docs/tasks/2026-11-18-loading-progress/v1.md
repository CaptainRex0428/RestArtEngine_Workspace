# v1 — 真实阶段、资源计数与连续加载生命周期

状态：实现与隔离验收通过。
基线：引擎 14a6b0d 加当前未提交 M1/M2/M3 与 native-inspector 工作；Windows / Debug。前一版：首次。

## 原因

原 interactive 路径只有 15% → initializePipeline → 65% → 100%；管线内部 9 Shader、224 PSO 及可选 DXR 没有反馈。SceneEditor.initialize 的 Engine / Project 资产、场景与索引阶段不计入加载，主窗口切换后反而绘制 65%。Project Manager 显示前执行了场景管线完整编译，而实际只画 clear/UI。

## 修改与验证

增加无 UI 依赖的可选同步 LoadProgress 与子范围映射。Renderer 在真实 Shader / PSO / DXR 步骤报告；Assets 在单次候选枚举、逐文件读取与事务发布后报告计数 / UTF-8 名称；SceneEditor 按实际子阶段映射。App 在 boot surface 完成工程加载，再切主窗准备首帧，保持单调进度、阶段 / 详情两行，节流同阶段刷新。Project Manager 改为仅初始化 device，避免重复编译无用场景管线。新增可选 --loading-report JSONL，保留完整事件与是否提交 UI，正常启动不写证据。回调只可 clear/UI/present，不重入 renderer resize / scene render，消息处理只记录窗口状态。

文件归属：主 agent 负责 Core header、MinimalApp、LoadingScreen 与其测试、公开文档、记录和集成；资产 worker 负责 Library / Registry / SceneEditor 初始化及资产回调测试；renderer worker 仅修改 initializePipeline/createPipeline 与接口。其他 native-inspector 源码继续保留；不在共享 build/cmake-vs2022 中构建或覆盖其运行程序。
