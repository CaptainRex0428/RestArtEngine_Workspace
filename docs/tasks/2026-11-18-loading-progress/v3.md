# v3 — 最后准备阶段保持小加载窗口

状态：实现与独立窗口验收通过，尚未提交引擎修改。
基线：已推送 7e5ca88 加当前后端／Inspector 未提交工作；上一版：[v2](v2.md)。

## 分析

用户截图显示 `Preparing initial scene and workspace` / 99% 占满编辑器大窗口，并带标题栏，与开头无边框小加载窗口不一致。v1/v2 虽然推进到首帧后才 Ready，却在第二窗口按 80% 屏幕尺寸创建后再次绘制加载图，导致本次显示回归。之前验收只查进度单调与提交，没有约束不同阶段的原生窗口尺寸。

## 修改

MinimalApp 记录首个加载窗口的最终图片比例与居中矩形；第二阶段先以相同 WS_POPUP、尺寸、位置与禁用 chrome 创建，99% 仍绘制同一小加载界面。先在小窗口背后预热场景上传／加速结构，不在这个尺寸建立编辑器 Dock 布局；随后隐藏、恢复正常窗口框架、调整至 80% 编辑器大小并渲染真实首帧，再显示编辑器。加载图不再绘制到大窗口。普通自测固定窗口路径保持原行为。

JSONL 增加实际客户区宽高与无边框标志。Test-LoadingProgress 检查所有实际加载页提交的尺寸一致、始终无边框，并要求最后准备步骤也有一次小窗口提交；约束来自真实 Win32 窗口状态，不只查源码或硬编码阶段名。
