# v1 — RHI 管线绑定契约反射校验

状态：通过（反射校验、双 API 实拍管线验证）
基线：`1bb5110` + 本轮工作区改动；Windows / DX11 + DX12；Debug x64
前一版：首次尝试

## 分析

`IRenderBackend::createPipeline` 只校验 HLSL 能否编译，不检查 PS 实际绑定了哪些资源。`RhiPipelineDesc` 也没有描述调用方打算使用的 `t0..tN / s0 / b0`，因此 shader 多读一张纹理、`b0` 尺寸写错或 VS 声明了额外输入时，要等到 draw 才表现为黑屏或错误采样；此时只能靠逐 Pass 回退排查。

审计记录（v1 任务 README）把“RHI post pipeline 尚无 D3DReflect 契约校验”列为未完成项；原生 `Scene.hlsl` 已有 `D3DReflect` 校验，RHI 缺少对应保护。

## 修改与验证

### 修改

- `RhiPipelineDesc` 增加 `sourceCount`（`t0..t{sourceCount-1}`，0–3）与 `constantBufferSize`（`b0` 字节数，0 表示不读常量）。
- `src/Renderer/RenderBackend.cpp`：
  - DX11 在编译后用 `D3DReflect` 取 `ID3D11ShaderReflection`；
  - DX12 在 DXC 编译后用 `IDxcUtils::CreateReflection` 取 `ID3D12ShaderReflection`；
  - 两条路径共用同一个校验函数：SRV 数量与绑定必须匹配声明、采样器只允许 `s0`、常量缓冲只允许 `b0` 且字节数精确匹配、VS 输入只能是 `SV_VertexID`、PS 至少写一个 `SV_Target`，其它资源类型拒绝。
- `SceneRenderer` 的 7 条后处理管线补上真实声明：FXAA 16 B、运动模糊 176 B、TAA 208 B、Tonemap 112 B、Bloom 64 B、DOF 48 B；源数量分别为 1/2/3/2/1/1/2。
- `BackendSmoke` 更新全部测试管线声明，并新增：
  - DX11/DX12 负例：声明 0 源却读 `t0`、`b0` 声明 32 B 但 shader 为 16 B，都必须创建失败；
  - 用仓库里真实的 `Shaders/Private/Rhi/*.hlsl` 按 `SceneRenderer` 相同声明，在 DX11 与 DX12 上创建全部七条管线。

### 验证

| 命令 | 结果 |
| --- | --- |
| MSBuild Debug x64 | 成功，无 warning |
| `--backend-self-test --capture-dir artifacts/backend-reflect` | PASS，含两条新负例与双 API 真实 shader 契约检查 |
| `--taa-self-test --capture-dir artifacts/reflect-regression/taa` | PASS（TAA/FXAA/运动模糊/景深/SSAO/调色） |
| `Validate-Render.ps1 -Executable bin\windows-x86_64\Debug\RestArtEngine.exe` | PASS（前向/延迟、光追开关、Unlit、resize、normals、UI） |

证据：`artifacts/backend-reflect/`、`artifacts/reflect-regression/`、`artifacts/taa-reflect/`。

## 结论

- RHI 管线在创建阶段就会拒绝不符合固定绑定布局的 shader，DX11 与 DX12 报错口径一致；真实的七条后处理 shader 与 `SceneRenderer` 的声明能同时通过两条 API 的反射。
- 反射校验没有改变后处理链的启用条件；TAA 与渲染回归通过，说明没有因新校验静默回退。
- 限制：校验的是源码级绑定，不检查运行时 descriptor 是否绑定正确；DX12 反射依赖 DXIL 容器保留 reflection，若以后 `-Qstrip_reflect` 需另存 reflection blob；新增后处理必须同步填写 `sourceCount` / `constantBufferSize`。
- 未运行：`BackendTests` CPU 套件（本轮未配置 CMake）；接口只新增带默认值的字段，未改变生命周期行为。
