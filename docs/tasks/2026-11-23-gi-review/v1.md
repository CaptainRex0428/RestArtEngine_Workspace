# v1 审查与第一轮像素读回

基线为引擎 `8f7dd2c`。隔离取出该提交的 Cornell Box 和 Shader，原版严格 D3D11 各跑六帧，SSGI、DDGI 和关闭状态分别生成 bmp。原始输出在 `artifacts/gi-review/baseline/`。原版验证层也能为零，单看调度或 validation 无法发现以下问题。

| 现象 | 源码原因 | 修正 |
| --- | --- | --- |
| SSGI 首帧和实时编辑后的第一帧变暗，边缘串色 | 强制读取有效历史才能发射，半分辨率重建的垂直步距分母误用了步数 | 当前帧直接追踪，按实际采样点和几何重建，逐物体重投影通过深度检验 |
| 关 diffuse 或切 GI indirect 看不出实际贡献 | 漏乘接收端非金属比例，两种视图的强度或增益不同；DXR incoming specular 直接加到画面 | 漫反射、镜面分别计算，最终统一合成，艺术强度只乘一次 |
| 显示像重复打光 | 软件的反弹输入混入环境和高光；硬件 DDGI 的 SH 负系数被截断 | 单次延迟光照输出 HDR 基底、可反弹漫反射；保留 signed SH，重建完成后才限制负辐照度 |
| 探针串墙或变得迟钝 | 无可见性约束的跨探针 Gaussian；软件滤波输出又写回历史 | 消除跨墙滤波反馈，硬件使用六方向距离矩，屏幕空间路径按正面和距离验证命中 |
| 质量选项与开销不一致 | 软件固定 64×24，系数重复追踪，DXR 还会发起额外的视口工作 | 给每种算法独立预算，DXR 只派发活动探针，两个 SH 后端共用基函数 |
| 工具栏显示笼统或错误 | 状态 getter 重新拼接信息并解析状态字符串，DXR 激活被误判为屏幕 GI 停用 | 从当帧执行结果传回算法、硬件路径、质量与失效原因 |

`--raster-gi-self-test` 的首轮 513×385 Cornell 读回通过 D3D11、原生 D3D12，档位、首帧和零增益有差异断言。目检发现原始间接光在场景默认曝光下很暗，简单的“非黑”检查也无法证明非本地颜色传递。改进见 [v2](v2.md)。
