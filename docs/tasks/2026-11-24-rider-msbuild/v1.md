# v1　验证 Rider 实际启动的 MSBuild

基线为引擎 `8f7dd2c` 加上工作区中的渲染改动，环境为 Windows x64、Rider 2025.3.3 和 Premake 生成的 VS 2022 解决方案。

## 原因

Rider 在载入两个 C++ 工程时报告 MSB4019，导入目标退化成驱动器根目录下的 `Microsoft.Cpp.Default.props`。生成的工程引用 `$(VCTargetsPath)\Microsoft.Cpp.Default.props`，并为 Debug、Release、Dist 选择 v143。10:11 的 Rider backend 日志显示它已经发现 VS 2022，却自动选中了旧 .NET Framework 的 MSBuild 4.0。此时构建尚未执行 C++ 编译。

## 本机验证

用 `vswhere` 确认 VS 2022 同时提供 x64 MSBuild 和 VC targets。在当前解决方案的 Rider 设置中选择该实例的 64 位 MSBuild，执行 Debug x64 构建。Rider 的 ReSharper Build 日志记录 MSBuild 17.14.19，10:41:19 的 DearImGui、10:41:33 的 RestArtEngine 均构建成功，合计 0 错误。引擎有两条 C4459，来自 `app/NativeD3D12Smoke.cpp` 中名为 width、height 的参数遮蔽全局声明。

此次选择默认保存到解决方案个人层。其他贡献者会从各自机器的自动检测开始，因此继续在[第二版](v2.md)解决工程生成入口的问题。详见 [Rider 工具链设置](https://www.jetbrains.com/help/rider/Settings_Toolset_and_Build.html)。
