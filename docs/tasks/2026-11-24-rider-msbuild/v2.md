# v2　生成与本机 VS 安装对应的 Rider 工具链配置

前一轮[个人层构建](v1.md)已经定位原因。本版基于引擎 `8f7dd2c` 的公开构建配置，目标是让全新检出和只安装 Build Tools 的贡献者走同一入口。

## 实现

`Build.lua` 的 `vs2022` 入口调用 `Config.lua` 中的生成步骤。Windows 上的 `scripts/Generate-RiderToolset.ps1` 用 `vswhere` 从 VS 17.x 的所有产品类型中查找同时具备 MSBuild 与 x86/x64 C++ 工具的实例，检查 x64 MSBuild、C++ 默认属性文件和 v143 工具集的属性文件。仓库保存模板 `.idea/RestArtEngine.sln.DotSettings.template` 和生成器；包含安装路径的解决方案层在各机器上生成，由 Git 忽略。

刷新解决方案时，脚本更新 MSBuild 的版本及路径，保留该层的其他设置。个人层仍可覆盖项目选择。缺少合适工具链时，生成器报告需安装的组件并去掉检测结果中的旧路径。工具链识别方式来源见[微软的 MSBuild 查找示例](https://github.com/microsoft/vswhere/wiki/Find-MSBuild)和[C++ 组件筛选示例](https://github.com/microsoft/vswhere/wiki/Find-VC)。

## 验收

在同一台 Windows 机器的另一盘符建立新的临时 clone，检出 `8f7dd2c` 及其固定的子模块版本，加入本轮生成器和模板。该检出没有 Rider 的解决方案个人层。运行 `scripts/GenerateWIN.bat` 后，从生成的配置中读取 MSBuild 路径，使用这个程序在命令行编译整个 `RestArtEngine.sln` 的 Debug x64 配置。构建成功，耗时 16.67 秒，0 错误、8 警告。两条 MSB8029 来自临时目录，其余六条来自基线源码。

生成器还用模拟的 VS 安装布局覆盖多个产品类型、含中文和 `&` 的目录、工具链恢复与重复生成。重复运行得到一致配置，个人层文件保持原内容。真实 Rider 会话中的两项目构建见 [v1](v1.md)。全新检出验证走命令行，未在第二台物理机器上运行。

复用方法见[工具链排查经验](../../experience/RiderMsBuild.md)。本次记录的构建对应基线加生成器候选，提交状态由引擎仓库历史确认。
