# v1 — 从前台焦点追到 Project Settings 的 disabled 作用域

状态：通过
基线：`f20e445`；Windows 11、DX11 debug layer；`--editor-self-test`

## 现象

连续两次在 Content 面板拖拽前失败：

```
Native Content did not gain focus before the drag.
```

## 排查过程

### 1. 前台焦点

- 用 `GetForegroundWindow` 探测：当前前台属于 Harness 宿主进程（pid 46864），不是测试进程。
- 测试由非前台 shell 启动，Windows 的前台锁会拒绝 `SetForegroundWindow`。
- 修复：测试侧增加 `forceForegroundWindow`：`AttachThreadInput` 到前台线程 → `ShowWindow` / `BringWindowToTop` / `SetForegroundWindow` / `SetFocus` → 解除附加。输入 hook 与拖拽前都改用它。

修完后测试**越过了**该断言，说明前台问题解决；但随后暴露三个此前被挡住的问题。

### 2. 夹具目录复用

```
The registry did not classify .rasset materials.
```

`output/TwoSidedSerialization` 没有在写入前清理，上一次失败运行留下的 `.rasset` 让 registry 统计到 3 个而不是 2 个。修复：保存前 `remove_all(fixtureRoot)`。

### 3. 滚动目标增长

```
The end of a long mesh slot list could not be reached.
```

诊断值：`Scroll.y=441`、`ScrollMax=454`、`ContentSize=913`、`InnerRect=459`。首次 `SetScrollY(max)` 后内容布局把 ScrollMax 增大了 13px（一行）。修复：重新设置目标并再捕获，最多重试两次；失败时打印上述值，且不再调用需要 ImGui 上下文的 API（之前那次诊断调用了 `GetIO()`，直接触发断言并挂起）。

### 4. Project Settings 的 disabled 作用域（真实 UI bug）

```
Assertion failed: (0) && "Missing EndDisabled()"
```

- 给 ImGui 断言加临时窗口名输出：`Project Settings/ProjectSettingsContent`。
- 给 Project Settings 的 Begin/End 加影子栈，输出事件序列：`B132 B132 E116 B132 E116 ...`。
- 根因：后处理设置循环按 **UI 组**（`parameter.group`，如 “Anti-aliasing”）管理 disabled 作用域，但一个 UI 组可以包含多个 effect——“Anti-aliasing” 同时有 FXAA 和 TAA。两个都关闭时会连续 `BeginDisabled`，而只在组切换时 `EndDisabled` 一次，留下一个未关闭作用域。
- 修复：作用域归属**单个 effect**。每次遇到 `key == "enabled"`：
  - 若已有打开的作用域，先 `EndDisabled`；
  - 再根据该 effect 是否启用来 `BeginDisabled`。
  组切换时也关闭残留作用域。

```cpp
if (key == "enabled") {
    if (disabledOpen) { EndDisabled(); disabledOpen = false; }
    if (!enabled) { BeginDisabled(); disabledOpen = true; }
}
```

## 结论

- “环境问题”确实存在（前台激活），但只修它会让测试继续撞上三个既有问题：夹具复用、滚动容差、以及一个真实的 ImGui disabled 作用域 bug。
- 断言失败会让进程挂在对话框上；自动化里必须把 `IM_ASSERT` 当作失败并终止，不能等待。
- 修改仅在测试与 Project Settings 的 UI 作用域逻辑，不改变渲染输出。
