# v1 — 原生 D3D12 DXR transport、硬件 resolve 与 Realtime GI

状态：通过
基线：`79bf6d0`；实现提交 `c017ff8`（含公开文档），已推送。

## 范围

用户选择一次性补齐原生 DXR（阴影/反射/GI 一体的 DXR 硬件预览 + 渐进/实时 GI）。目标不是把旧 D3D11/D3D12 共享 bridge 藏到 native12 里，而是让 DXR 与光栅共用同一个 D3D12 device/queue。

## 实现

### HardwareRayTracing native 模式

- 新增 `initializeNative(ID3D12Device*, ID3D12CommandQueue*)`：QueryInterface `ID3D12Device5`，检查 DXR 1.1、SM 6.5、输出/HDR 格式，创建自己的 allocator、`ID3D12GraphicsCommandList4`、普通 D3D12 fence 和 descriptor heap；不创建 D3D11 device、不创建共享纹理/fence。
- `prepareOutput` native 分支创建普通 UAV 图像：RGBA8 输出、FP32 累积/法线/albedo、FP16 间接光；不创建 D3D11 shared handle/SRV。
- `render` native 分支跳过一次 DX11 fence 握手；DXR 仍用原 compute 管线。输出提交后资源状态置为 `COPY_SOURCE`，间接光置为 `PIXEL_SHADER_RESOURCE`，供 RHI 消费。
- 旧 bridge 路径完全保留（初始化/共享纹理/等待分支由 `native` 布尔隔离）。

### RHI 导入与消费

- `D3D12RhiDevice::importTexture(ID3D12Resource*, TextureDesc, currentState)`：包装外部 D3D12 资源为 RHI 纹理，只创建 SRV（`sampled=true` 时），不创建 RTV；资源生命周期由 DXR 模块持有，RHI 包装 AddRef。
- `wrapImportedTexture` 不做附件视图，避免 UAV-only DXR 图像被误当 render target。
- HardwareResolve native 分支把 DXR 输出复制到 `rasterDestinationImage`（场景色或 AA 源图），替换 D3D11 `CopySubresourceRegion`。
- Realtime GI：DXR 间接光每帧复制到 RHI 自己的 `RGBA16F` 纹理，再作为 t9 绑定到 Deferred/Forward 光照 Pass。这样两套 resource-state 状态机解耦；直接采样 DXR 资源会被 RHI/UI 的 sampled weak-list 改写状态。

### 管线与配置

- native12 初始化阶段始终创建/尝试 `HardwareRayTracing`；DXR 不可用时保留光栅并记录原因。
- `hardwareBackendAllowed` 对 native12 取决于 `nativeMode()`；`HardwareTransport`/`HardwareResolve` 进入声明式管线；Realtime GI 的 `IndirectLighting` 读取绑定到拷贝纹理。
- `ProjectSettingsRules` 现在允许 D3D12 请求硬件光追/GI；UI 标签改为 `D3D12 (native DXR)`，说明原生 DXR 与光栅共用设备；混合 bridge 说明保留。
- `BackendSelection` 启动原因、`RenderBackends`/`HardwareRayTracing`/`Architecture`/`EditorGuide`/`RenderingDevelopment` 已更新。

## 边界

- 原生 DXR 沿用当前“硬件图像整幅替换光栅颜色”的语义；不是逐像素 inline shadow/reflection 混合。DOF、Outline、解析光追和 GPU 裁剪计数仍未迁移到 native12。
- 未实现 DispatchRays/SBT（仍 RayQuery compute）、运动重投影、透明/蒙皮、多视图历史、异步多帧提交。
- DXR 不可用或 pipeline 编译失败时保留光栅并报告原因；工程请求不被静默改写。
- 每帧 DXR 提交后 CPU 仍等待上一帧 fence（与原 bridge 一致），不是异步队列优化。
