# v2 — 编辑器视口偏移导致的 DXR 画面错位

状态：通过
基线：`c017ff8`；修复提交 `64a7c97` 已推送。

## 现象

用户开启 native DXR + Path tracing Progressive 后，编辑器 Scene Viewport 出现错位：画面右侧留下一条浅色/未更新的竖带，左侧看起来像旧光栅或错位图像；顶部 GI 计数持续增长，说明 DXR 在跑，但合成位置不对。

## 根因

编辑器 Scene Viewport 不是整张 scene target，而是其中的一个子矩形：`settings.viewportX/Y/Width/Height` 由 `ViewportInteraction` 根据面板位置与画面矩形设置。native HardwareResolve 只把 DXR 输出复制到 `rasterDestinationImage` 的 `(0,0)`：

```cpp
copyTextureRegion(rasterDestinationImage, image, 0, 0, viewportWidth, viewportHeight);
```

而 D3D11 路径使用 `CopySubresourceRegion(destination, 0, viewportX, viewportY, ...)`。于是 DXR 图像总在 target 左上角，编辑器却按 `viewportX/Y` 采样子矩形，得到错位图像，右侧留下的旧内容是未覆盖区域。

## 修复

- RHI `D3D12RhiDevice` 新增 `copyTextureRegionTo(destination, dstX, dstY, source, srcX, srcY, width, height, layer)`；原 `copyTextureRegion` 改为委托 `(0,0)` 版本，行为不变。
- native HardwareResolve 改为在 `(viewportX, viewportY)` 解析 DXR 图像。
- native self-test 增加回归：
  - 同一 scene target 上渲染 viewport `(0,0,200,140)` 与 `(64,48,200,140)`；
  - 比较 origin 区域与 offset 区域的像素，AA 关闭要求完全一致；
  - 再以 FXAA 重复，允许视口边缘小数邻域误差（实测 2 像素，阈值 8）。
- 保存 `native-dxr-editor-*-offset.bmp` 作为证据。

## 验证

- `--native-d3d12-self-test`：exit 0；报告 `dxrViewport.mismatches = {disabled:0, fxaa:2}`。
- 临时还原旧 copy 行为后同一测试失败：`18007 mismatched pixels`，证明测试能抓住该回归。
- CTest **30/30**。
- Sandbox native DXR 运行时（非编辑器）仍 validation 0；编辑器视口专项与运行时路径分别验证。
- 修复后编辑器视口整幅 DXR 图像按 `viewportX/Y` 对齐，不再有右侧错位带。

## 边界

本修复只解决合成偏移；DXR 仍是整幅硬件预览替换场景色，DOF/Outline/解析光追 native 未迁移等边界同 v1。
