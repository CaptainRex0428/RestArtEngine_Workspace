# v5 — 明确分离 Scene、Asset 和 Save All

状态：通过；前版 [v4](v4.md)。用户指出场景仅应保存引用与配置，明确要求进一步拆开职责。v4 的增量网格优化已解决重复写大模型，但 Save Scene 仍调用了资产保存，不满足新的严格边界。

## 分析

Save Scene／Save As 仍保存资产；Save material assets 顺带保存场景；Apply material 设置 sceneDirty；全局 materialsDirty 无法表达仅保存一个材质。场景保存还校验几何，和只存 GUID 的职责不符。UI Import／Copy to Project 已发布独立文件，但 New material 与底层 API 新资产尚在内存，不能直接保存悬空 GUID。

## 修改与验证

- Save Scene／Save As 仅写 Actor／引用，不保存或清除资产 dirty。使用新鲜、不加载缩略图的 Content 索引检查可加载的引用；未落盘／缺失依赖明确提示 Save Asset／Save All，旧兼容图元可从代码恢复。
- Apply 只标记对应材质 dirty；Save material asset 仅保存选定已应用材质；New material 正常创建即独立落盘；失败仍保留未保存材质供重试。批量 Save All 按资产差异保存，然后场景／配置。
- World::save 不访问几何载荷，几何完整性校验移到实际资产写入前；未修改现代材质跳过重写。
- 新增材质独立保存测试，调整 World 测试，编辑器验证未保存／缺失依赖、场景不写已修改资产、材质不写场景或其他资产、dirty 隔离及 Save All。
