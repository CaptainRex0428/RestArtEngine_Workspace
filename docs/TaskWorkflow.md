# 开发任务闭环

Codex、DeepSeek（补充模型）、主 agent 和专项 agent 共用本流程。每次开发任务按 **分析原因 → 修改与验证 → 记录版本日志 → 总结经验** 收尾。修复、功能、性能优化、构建和协作配置任务均适用；纯问答或只读咨询不自动变成开发任务。简单任务四部分可各写一句，不为凑格式增加测试或审批。

## 1. 分析问题原因

先读当前任务日志及 [经验索引](DevelopmentExperience.md)，再核对源码、工作区与相关领域文档。记录用户现象／目标、复现条件、基线、影响范围和验收条件。区分已证实原因、待验证假设及环境问题；以日志、代码路径、最小复现或测量支持判断，不能把猜测写成根因。新增功能分析现有能力缺口；文档任务分析规则缺失或矛盾，不强行编造故障。

## 2. 修改与验证

围绕已确认原因修改，说明方案、文件归属、兼容边界与可能受影响的功能。保留其他任务和用户资产。按 [交付技能](../../.agents/skills/restarengine-delivery/SKILL.md) 选择验证，记录实际命令、构建／源码身份、预期和结果；性能前后对比保持输入和设置一致，说明负载波动。失败时回到分析，不无证据地重复同一尝试。未验证、失败和通过分别标记，不能只凭编译成功宣称交互或画面正确。

## 3. 记录问题修复日志

每个任务建立 `local/docs/tasks/YYYY-MM-DD-<task-slug>/`，目录名描述问题且不含机器信息。使用 `README.md` 保存目标、当前状态、最新版本链接、待办及经验入口；具体尝试放 `v1.md`、`v2.md`、`v3.md`……，数字不限位数。版本号是同一任务的分析／修复迭代，和引擎发行版本、DevLog 期数、Git commit 无关。

- 首次分析建 v1；同一尝试可补齐验证与结果。新的修复策略、根因修正或失败后的实质重试创建下一版本并链接上一版。仅文字订正无需新增版本；已结束尝试不覆盖成成功记录，后续更正注明日期和依据。
- 每版写：现象与基线、原因及证据、修改范围、验证命令与实际结果、失败／限制、下一步、经验处理。提交后可补 commit；未提交就明确写未提交。
- 原始 stdout、Trace、截图和大文件保留 `artifacts/<task-slug>/vN/` 或已有忽略目录；任务日志保存可跨机阅读的文字结论与证据位置。原始文件缺失时标记不可复核，不据旧 PASS 冒充当前验证。
- 主 agent 负责版本和索引，子 agent 回报证据与经验候选，避免多人改同一日志。并行的不同问题使用不同目录；同一问题由指定写入者分配版本号。
- 完成时 `DevelopmentStatus.md` 仅新增摘要与任务索引链接；完整过程保留在任务目录。中断时更新当前状态、阻塞与下一步，不把未完成任务写成完成。

最小版本模板：

```markdown
# v1 — 本轮修复目标
状态：分析中／实现中／待验证／未通过／通过／阻塞
基线：引擎 commit、相关未提交差异或源码快照；平台／配置
前一版：首次尝试或相对链接

## 分析
现象／复现；已确认原因和证据；尚待排除的假设。
## 修改与验证
涉及文件及行为；实际命令、预期与结果；证据位置；失败与未验证项。
## 结论与经验
是否满足验收、剩余问题和下一步；新增／更新／复用的经验条目链接及理由。
提交状态：未提交或实际 commit；推送状态单独说明。
```

## 4. 总结经验并维护经验文档

先查 [DevelopmentExperience.md](DevelopmentExperience.md) 及相关主题经验。已有同类结论就补充适用条件、反例和验证方法；新主题再建 `local/docs/experience/<topic>.md` 并加入索引。每条经验包含触发场景、原因、处理原则、防回归方法、适用边界和来源任务／证据；避免只有“以后注意”的口号。

经验是可复用的判断依据，任务日志保存具体经过。已经写在领域规范或技能里的规则直接引用，不在多处复制正文。新证据推翻旧经验时保留更正依据，更新索引；本轮无新增经验也要注明复用哪条或为何不产生通用结论，不为数量编造经验。只有能改变执行行为的稳定规则才提炼到相关 skill。

## 完成、存放与授权

任务交付前检查四项是否闭环：原因清楚且不确定项已标明；修改完成且验收有证据；版本日志与索引已更新；经验已新增、修订或明确复用。无法验证的任务标为待验收，说明具体缺口。

任务日志和经验文本只属于 `local/` 协作仓库，不进入引擎仓库；原始证据不进入两个仓库，禁止记录凭据和机器配置。规则见 [RepositoryPolicy.md](RepositoryPolicy.md)。新增这些目录已受引擎忽略 `local/` 的规则保护。修改运行 skills 后按 [WorkspaceSync.md](WorkspaceSync.md) Collect，继续在 RAEngine 根使用原调用路径。记录完成不代表自动授权 commit、push、发布或写 DevLog。

历史任务不批量重写或伪造 v1/v2；以后续实际工作开始采用此结构，旧日志可直接作为来源引用。
