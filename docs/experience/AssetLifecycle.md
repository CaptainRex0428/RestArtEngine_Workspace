# 资产重导入与删除一致性

## 稳定身份与数据更新

场景：原路径或新路径重新导入已经被 Actor 引用的网格。原因：GUID 保留解决引用稳定，但不能单独保证 GPU、包围盒、预览和保存缓存识别变化。

做法：隔离解析，保留 GUID／名称／目标位置，先写临时文件，再替换磁盘和内存。发布后刷新几何版本与持久化基线；候选构造、缩略图和可分配结果准备在发布前完成。验证同顶点数量但坐标变化的网格、失败后的字节／缓存键不变，以及磁盘重载和后续增量保存。

边界：此事务针对明确的重新导入操作，不代表普通批次导入可以自动覆盖。来源路径只在成功后切换，源文件保持原样。

## 删除与引用恢复

场景：删除已加载的项目网格／材质。原因：只删文件会被后续保存重新生成，只查活 Actor 会遗漏保存场景及 Undo／Redo 闭包中的引用；现代容器删除后同 GUID legacy 文件也可能重新加载。

做法：同时核对项目文件归属、完整的保存场景引用、当前场景和编辑状态；磁盘删除成功后再移除内存库。当前 UndoStack 不提供引用查询，因此确认框说明成功删除会清空相关场景历史，取消／失败不得清除。重复 GUID（含 legacy fallback）明确拒绝，不擅自连带删除历史文件。

验证：场景引用、损坏引用字段、重复身份均阻止删除；成功后 Save All／重载不复活，源文件仍存在。安全依赖扫描不能复用浏览器跳过无权限目录／错误头的尽力扫描。耗时扫描后重新核对目标类型、大小、修改时间及身份，防止删除扫描期间已变化的文件。

边界：引用扫描限当前 Content；不是完整场景有效性校验，不处理跨工程引用或 Shader include 图。场景删除的旧缩略图 sidecar 清理不在本轮新增范围。
