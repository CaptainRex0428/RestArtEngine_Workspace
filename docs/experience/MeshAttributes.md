# 多材质与可选网格属性

## 面材质索引、资产GUID与实例绑定分开

场景：导入一个带多个源材质的合并网格。源面的材质ID是源节点材质表的局部索引，不能直接作为引擎材质GUID，也不能用合并后的Actor单材质代替。FBX实例必须查node.materials；相同源材质可合并，但同名的不同材质不能只按名称去重。将面按Slot分桶得到连续section，避免交错源面造成逐面draw。

实例覆盖、网格默认与兼容fallback按固定优先级解析，并把同一规则用于光栅、光追、草稿、拾取和引用保护。BVH候选阶段按面的Slot过滤Cull/Never；先求最近几何再拒绝会漏掉后方有效表面。验收使用同一mesh的红/蓝两个section，分别改一槽与另一个Actor实例，并比较实际像素、undo和保存重载。

## 稳定来源键必须在读写两端一致

场景：DCC重排材质表、重导出含无关的材质记录。数值槽序号不稳定；保存并按唯一来源key匹配。来源key仅依赖真正导入的网格节点所引用材质，完全未连接的同名记录不应改变序号。无法唯一识别的重名FBX重导入明确拒绝，保留原文件与内存，不能靠猜测交换绑定。

有效key为非空sourceKey，否则name。资产读/写与场景保存都要验证同一有效key唯一，否则会出现“保存成功、原样重载失败”。覆盖显式key与回退name碰撞的反例，而不只是两个sourceKey重复。只改变单slot兼容fallback的几何/来源不应清撤销历史；多slot布局变化需要处理索引历史，不能简单沿用旧闭包。

## UV按面角保存，且避免扩大无属性网格

场景：同一空间顶点有不同UV接缝，或千万面旧场景本来没有UV。按三角化corner获取UV indices→values，镜像调整绕序时同步所有属性。最多四通道并明确截断反馈，保留源坐标与通道名，不把识别UV描述成UV展开/纹理图集。

独立可选流保留无UV的24B位置法线顶点；射线只为有UV三角形记录属性索引，并共享同mesh各实例的UV顶点，避免给每个80B三角形无条件追加96B。原位UV/section修改进入geometry revision与GI历史；少量slot名称/default元数据单独比较，静态帧不扫描全量UV。用同大小修改、恢复、shader四通道输出、DXR/软件ray及无UV10M基准验证。
