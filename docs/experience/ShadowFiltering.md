# 阴影抗锯齿与过滤经验

场景：默认阴影边界出现硬阶梯，用户要求阴影抗锯齿。截图表明问题在阴影贴图的**空间覆盖率**，不是最终颜色缺少后处理。

## 原因

- 阴影图 2048² 覆盖 30 世界单位，每 texel 约 1.46 cm；靠近相机时一个 texel 覆盖多个屏幕像素。
- 默认 2×2 PCF 只做 4 次双线性比较，过滤器宽度不足以跨过可见 texel 阶梯。
- FXAA/TAA 作用于最终颜色，无法恢复阴影图没有记录的覆盖率；TAA 只能通过相机抖动在稳定画面里缓慢平滑，不能作为阴影 AA 的主方案。

## 做法

- 分辨率翻倍到 4096²，texel 世界覆盖减半；两层 CSM 深度数组约 128 MiB。
- 新方法 `ShadowMapPCF16`：4×4 固定偏移、16 次 `SampleCmpLevelZero`；每次比较自带 2×2 双线性，有效覆盖约 8×8 texel。固定偏移（而非随机旋转）保证静态阴影不闪烁，代价是每像素 16 次比较。
- 默认方法改为 PCF16；2×2、3×3、硬比较、PCSS、CSM、GTAO、Contact、Analytic、Disabled 均保留，低端设备可显式降级。
- 枚举、`RenderFeatures`、Scene 下拉、EditorSmoke 捕获和公开文档必须同步；漏一处会导致诊断或 UI 与实际过滤不一致。

## 验证

- CTest 全量、原生 D3D12 套件、Debug 构建。
- 同一场景下 2×2 与 4×4 的固定裁剪对照图（左阶梯、右平滑），保存到公开文档；不以“画面变了”代替质量判断。
- 编辑器自测的原生窗口 focus 断言与阴影无关，失败不能归因于阴影。

## 边界

4×4 PCF 是空间过滤，接触硬化/大范围半影仍应使用 PCSS 或解析/硬件光追；PCSS 的时域降噪、级联动态分辨率、局部灯独立阴影图尚未实现。4096² 阴影图对低显存设备不友好，需要后续做质量档位。
