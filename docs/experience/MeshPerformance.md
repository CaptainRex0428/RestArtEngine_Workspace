# 大网格性能经验

## 静态数据不能在每个 Pass 重扫

场景：导入后持续卡顿，模型未变化仍产生大量 CPU 工作。R8 任务确认每个绘制 Pass 哈希整份几何、DXR 每帧展开全场三角形、拾取逐面变换是主要开销；资产文件大小和用户感知面数都不能代替实际索引计数与测量。

做法：先记录真实三角数、顶点数、配置和 CPU／GPU 证据，再使用显式几何版本、小规模场景输入签名与局部空间 BVH。原位几何编辑须调用 `markGeometryModified()`；完整契约见 [AssetFormat](../../../docs/AssetFormat.md)，渲染边界见 [RenderingDevelopment](../../../docs/RenderingDevelopment.md)。每增加影响输出的材质状态，必须同步检查所有缓存键。

验证：覆盖不变输入复用、同大小缓冲原位修改、同 ID 替换、删除与预算淘汰、变换和材质修改；用实际 GPU 像素检验失效与恢复，不能只看版本数。拾取检查孔洞、最近命中、单双面、镜像与非均匀缩放。

边界：首次 bounds／BVH 构建和上传仍有成本；当前世界空间 DXR 数据在实例变化时仍需重建。缓存优化不能冒充按 Mesh BLAS／TLAS 更新，也不能用降画质制造等价性能结果。

## 测量与加速结构构建

R8 的 Debug BVH 构建采用逐层比较划分时接近 9.75 秒，改为 Morton 编码、基数排序与叶包围盒一次计算后测到约 0.63 秒。仅适用于该实测输入；空间分布与重复编码会影响树质量，须测试乱序、重复键及真实几何，不能把一种数据集的结果推为所有模型表现。

对比固定模型、分辨率、采样和测量区间；分别报告首次准备、稳态查询、CPU 提交和 GPU 等待。保留预热规则及负载波动，不只选最快一次。截图相同能支持画面一致，不能单独证明性能因果；CPU scope 也不是 GPU 时间。
