# 大网格性能经验

## 静态数据不能在每个 Pass 重扫

场景：导入后持续卡顿，模型未变化仍产生大量 CPU 工作。R8 任务确认每个绘制 Pass 哈希整份几何、DXR 每帧展开全场三角形、拾取逐面变换是主要开销；资产文件大小和用户感知面数都不能代替实际索引计数与测量。

做法：先记录真实三角数、顶点数、配置和 CPU／GPU 证据，再使用显式几何版本、小规模场景输入签名与局部空间 BVH。原位几何编辑须调用 `markGeometryModified()`；完整契约见 [AssetFormat](../../../docs/AssetFormat.md)，渲染边界见 [RenderingDevelopment](../../../docs/RenderingDevelopment.md)。每增加影响输出的材质状态，必须同步检查所有缓存键。

验证：覆盖不变输入复用、同大小缓冲原位修改、同 ID 替换、删除与预算淘汰、变换和材质修改；用实际 GPU 像素检验失效与恢复，不能只看版本数。拾取检查孔洞、最近命中、单双面、镜像与非均匀缩放。

边界：首次 bounds／BVH 构建和上传仍有成本；当前世界空间 DXR 数据在实例变化时仍需重建。缓存优化不能冒充按 Mesh BLAS／TLAS 更新，也不能用降画质制造等价性能结果。

## 测量与加速结构构建

R8 的 Debug BVH 构建采用逐层比较划分时接近 9.75 秒，改为 Morton 编码、基数排序与叶包围盒一次计算后测到约 0.63 秒。仅适用于该实测输入；空间分布与重复编码会影响树质量，须测试乱序、重复键及真实几何，不能把一种数据集的结果推为所有模型表现。

对比固定模型、分辨率、采样和测量区间；分别报告首次准备、稳态查询、CPU 提交和 GPU 等待。保留预热规则及负载波动，不只选最快一次。截图相同能支持画面一致，不能单独证明性能因果；CPU scope 也不是 GPU 时间。

来源：[R8 任务记录](../DevelopmentStatus.md#r8-大网格运行与拾取性能优化2026-10-29)，引擎提交 `2c84e99`，历史原始证据 `artifacts/r8-performance/`。本页提炼历史验证，不表示本轮重新运行引擎。

## 场景保存不能反复重写静态资产库

场景：视口面数很低，但保存无响应。先核对场景引用和 Content 全库的区别；未在场景中的大型模型仍可能被全量保存。Save Scene 任务在约 326 MB R8 副本上确认旧路径每次保存约 78～89 秒，主要是网格重复序列化、CPU 缩略图与写盘，不是由截图可见面数决定。

做法：首先分离职责：Scene 保存 Actor 和引用，Asset 保存载荷，Save All 协调两者。前期 v1/v4 仅用缓存避免全量资产重写，用户随后指出保存边界仍耦合；[v5](../tasks/2026-10-29-save-scene/v5.md) 将资产写入和几何验证从 Scene 路径移除。场景只检查依赖已发布，不把未保存的材质／网格修改偷偷写盘或清除 dirty。

资产侧仍使用持久化基线：现代资产成功加载／发布／保存后，以几何版本、序列化元数据、目标路径和文件状态判定是否需要写入。只在成功后建立基线，失败可重试；缓存不替代新资产保存、格式迁移或缺失文件重建。几何验证放实际资产写入之前；数值包围盒在数值数组上计算，避免逐顶点查询和转换 JSON。新建／导入 UI 应先发布资产再使用 GUID；纯内存新资产需要显式保存，Scene 不得产出悬空引用。

验证：分别测试资产未引用／引用、加载后第一次保存／重复保存、同尺寸原位修改并标记版本、深复制／替换、移动／删除／外部文件变化、失败重试、旧格式迁移。低层计时之外，用真实编辑器 Save Scene／Save As／Save All 检查路径、dirty 状态、保存后重载。只使用隔离工程及模型副本；同时观察文件字节／mtime，不能仅靠“写入速度快”推断正确跳过。

边界：原位编辑必须 `markGeometryModified()`；大小＋mtime 不检测保持两者相同的外部内容篡改。首次或实际修改的大网格仍同步保存，不把增量缓存称为异步保存。场景 JSON 已使用临时文件替换；资产容器仍直接写入，不构成跨文件事务，失败重试不等于所有旧文件无损。
