# 共享工作区集成经验

场景：多个任务改同一头文件、渲染器或测试入口。完整工作区构建通过，不代表其中一个任务的独立提交能编译；只按文件暂存会混入其他任务，过度拆分又可能漏掉依赖。

做法：先确认任务边界与实际 diff；需要部分提交时基于 HEAD 构造候选，只改索引，保留工作文件。对候选导出隔离源码快照，补齐固定版本子模块后构建，核对最终暂存清单。若存在不能拆开的真实依赖，明确纳入授权范围或保留为待提交，不提交已知不可用的半套接口。

验证：检查暂存差异、独立候选构建、相关测试，以及提交后其他任务仍在工作区。运行期间的新材质字段、统计和剔除可能改变测试预期；先分析真实语义，再覆盖新旧模式，不能删除失败断言来获得通过。

边界：这一额外快照流程适用于混合改动和真实依赖风险；简单完整改动无需重复全量构建。原始日志、截图和源快照保留忽略目录；协作库仅记录摘要与链接。

整理资产相关提交时，先核对示例场景的引用闭包。用户要求测试模型留在本地，则引用该模型的场景也必须留在本地；不能为清空 Git 状态擅自删除模型、改写场景或漏交依赖。公开技术文档要与已提交的示例一致，不能把仅在本机完成的场景迁移写成干净 clone 已包含。此次应用见 [剩余提交任务](../tasks/2026-10-29-remaining-commits/README.md)。
