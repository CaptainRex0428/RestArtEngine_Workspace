# 独立 D3D12 主后端与 D3D11 回退（2026-11-18）

状态：**提案，未实现**。用户已确认独立 D3D12 主渲染后端与可选 D3D11 回退两个目标；下述配置字段、迁移策略和阶段是设计建议，不代表现有接口。引擎基线 `14a6b0d`。

关联：[本轮讨论](../conversations/2026-11-18-native-d3d12-backend.md)、[Pass/RHI 学习](../learning/PassGraphRhiRelationship.md)、[此前诊断建议](RenderingDiagnosticsFocus.md)。本方案取代此前“Inspector 先行、RHI 暂缓”的近期优先级，保留 Inspector/HDR 长期目标。

## 目标与现状缺口

目标执行链为：场景／材质／相机 → 共享 Pass 与资源声明 → 实际 RHI → D3D11 或 D3D12 → 视口与编辑器呈现。后端是二选一的主渲染执行路径，DXR 是可选 Feature。

当前源码尚不满足：

- `src/Renderer/RenderBackend.cpp` 只有生命周期占位，Windows 的 Auto 选择 DX12 不意味着可以画场景；实际 App 直接创建 SceneRenderer。
- SceneRenderer、ImGui、预览纹理和加载界面依赖 D3D11 device/context/SRV。
- `SceneRenderer::initializePipeline` 无条件创建 DXR bridge；关闭 hardwareRayTracing 主要阻止执行，不能保证不初始化 D3D12。
- 现有 DXR 通道依赖 D3D11，另建同卡 D3D12 device，以共享图像／fence 交互。它不能充当独立 D3D12 后端。
- 当前 Pass 声明只有语义资源 bitmask 与先生产后消费校验，未描述具体资源状态、子资源和生命周期。

## 选择契约

建议用户请求保存到工程配置：`backendPreference = Auto | D3D11 | D3D12`、`allowFallbackToD3D11`；硬件光追、反射／阴影、GI 等请求继续独立保存。实际后端、实际 Feature 和原因只作为运行状态，不能反写覆盖用户请求。

| 请求／条件 | 建议行为 |
| --- | --- |
| 明确 D3D11 | 严格 D3D11，不创建 D3D12 device／DXR bridge；保留 DXR 请求并说明未生效；D3D11 可用的解析／软件路径按原语义执行 |
| D3D12 可用但没有 DXR | D3D12 光栅正常工作；禁用所需硬件能力不足的 Feature，说明原因 |
| D3D12 启动失败，允许回退 | 清理失败实例后启动 D3D11，显示请求值、实际值与失败阶段／原因 |
| D3D12 启动失败，禁止回退 | 明确启动错误，不静默更换后端 |
| Auto，D3D12 仍处实验阶段 | 继续选择已验收的 D3D11；实验 D3D12 仅供显式选择 |
| Auto，D3D12 达到完整基线 | 优先选择 D3D12；不满足必需条件时，按回退开关决定尝试 D3D11 或报告错误 |

Auto 在实验阶段直接选择 D3D11 属于初始选择；D3D12 成为默认候选后的失败转用 D3D11 才属于回退。避免同一开关在 UI、日志与代码含义不同。

选择需要同时检查：编译实现是否存在、驱动／设备能力、当前运行模式必需资源与管线能否初始化。`D3D12CreateDevice` 成功只是其中一项；不能以支持 DXR 代替支持 D3D12 的判断，也不能凭三角形演示让 Auto 切换完整编辑器。

后端选择首版在启动时生效。界面显示当前实际后端与“下次启动生效”的请求值；普通材质／灯光数值仍实时反馈。运行中热切后端、设备丢失恢复分别立项，不承诺启动回退覆盖它们。命令行覆盖应仅作用于本次启动，用于诊断和故障恢复，不偷偷保存到工程。

回退须区分缺失后端／设备能力不足等预期不可用与通用 Shader／资产／程序错误。后者不能笼统吞掉后标记启动成功；诊断保留原始失败。具体可回退错误类别需在实现时形成测试表。

## 旧项目与现有 DXR 的兼容

旧工程没有后端字段，且可能请求现有混合 DXR。不能直接把其历史行为标成“严格 D3D11”，也不能清除用户的 GI／光追配置。

迁移期间保留明确标识的旧混合路径作为兼容过渡，与新严格 D3D11 和原生 D3D12 区分。缺字段工程的读取规则、首次显式选择后的保存规则需一起实现和测试；若原生 D3D12 尚未覆盖所需 DXR，界面说明限制，不能静默把旧工程降级。最终再设计移除旧路径的条件，不在首个选择器提交中顺带删除现有光追。

## RHI 与显式资源声明一起落地

RHI 公共边界提供有类型的 buffer／texture／view 句柄与描述、资源上传、图形／计算管线、绑定、Draw／Dispatch／Copy、提交／呈现与安全销毁。平台对象留在后端内部；共享 Pass 不能接收 D3D11 context 或 D3D12 command list 才能执行。

先用现有 D3D11 画面证明一条真实调用链通过 RHI，再由 D3D12 实现同一契约。不要只包装 SceneRenderer 或添加更多空后端类。API 无关边界同时考虑未来 Vulkan/OpenGL 和平台差异，但本轮不创建未实现的平台目录来充数。

Pass 声明至少包含：

- 实际资源／版本身份、读写用途、必要的子资源范围，以及导入／外部资源。
- 颜色／深度附件及 load/store 操作，clear、upload、copy、readback、UI 采样与 present 的用途和执行边界。
- 资源的生产、消费及 GPU 使用结束时间；持续存在的输出／历史资源与瞬时资源区分。
- 参数／绑定布局。静态 sampler 无须伪装成纹理图边；有写入、同步或生命周期依赖的常量／上传缓冲必须纳入追踪，不能全部留作隐式状态。

D3D11 据此处理绑定冲突与执行顺序，D3D12 据此记录资源状态转换和同步。首版可以按固定顺序执行并校验，不要求先实现自动别名、Pass 裁剪、多队列调度或完整 Render Graph。

## 分阶段实施与验收

| 阶段 | 实际交付 | 通过条件 |
| --- | --- | --- |
| M1 后端选择／生命周期 | 真实 App 启动链消费选择、请求／实际状态、错误分类与过渡兼容；阻断严格 D3D11 的 DX12 初始化 | 严格 11 无 D3D12 设备；缺失原生 12 能清楚报错或按设置回退；旧混合工程仍可读取、执行且配置不丢 |
| M2 实际 RHI 与资源声明切片 | 现有 D3D11 的上传→目标／绑定→真实 Mesh Draw→视口显示链走 RHI，Pass 声明驱动真实资源使用 | 固定相机／场景与旧路径图像对照；相机材质实时变化正确；没有用 native context 绕过公共接口来伪造完成 |
| M3 原生 D3D12 最小闭环 | device／queue／swapchain、帧 fence、描述符、上传与延迟销毁，同一 RHI 绘制真实场景并完成 ImGui／视口呈现 | 不依赖 D3D11 device、D3D11On12 或旧共享 bridge；真实 Mesh／材质／深度、UI 和 resize 可用，标记实验后端 |
| M4 编辑器与管线覆盖 | Forward／Deferred、阴影、后处理、Outline、四视图、预览／缩略图、加载界面、捕获、诊断、热编译与关闭恢复 | 按能力矩阵逐项 GPU／交互验收；未覆盖项明示；达到必需基线前 Auto 不优先 12 |
| M5 原生 DXR 与性能 | DXR 复用主 D3D12 device／资源体系，逐步减少跨 API bridge；测量后优化 | 反射／阴影／GI 请求与实际状态正确，原生 12 无 DXR 仍能光栅；同场景画面／CPU／GPU／显存对照 |

M2/M3 按完整纵向切片推进：先简单场景与 UI，随后迁移更多 Pass。具体头文件接口在首个切片前冻结；共享声明、构建入口、App/ImGui 由唯一写入者集成，避免各模块自己拥有设备。

第一项实施工作应是 M1 的真实配置／生命周期与失败状态，随后推进 M2；M1 结束仍不得宣称原生 D3D12 已实现。需要真实 D3D12 才能验收的回退故障在 M3 补齐，M1 用缺失实现／可控故障验证策略。

## 验证矩阵与风险

- 启动：Auto／11／12 × 回退开关 × 未编译／设备不支持／初始化成功；检查工程往返保存、临时命令行覆盖、请求值不变。
- 特性：原生 12 光栅不依赖 DXR；有无 DXR、开关、渐进／实时 GI；严格 11 不暗建 12；旧混合模式单列。
- GPU 生命周期：连续 resize、最小化恢复、多视口／工具预览、捕获冻结、GC、退出；UI 借用纹理与 GPU fence 共同决定退役安全。
- 画面与编辑：同场景／相机／分辨率基线；实时数值、Shader 成功替换／失败保留、材质草稿与保存、Actor 拾取／Outline、四格独立视图。
- 诊断：实际 Pass／资源身份用于后续 Inspector；API debug layer、资源名称和事件标记支持外部 RenderDoc。纯 D3D11、纯 D3D12、旧混合捕获分别实测，不能由工具支持 API 推断组合可用。
- 性能：D3D12 不保证自动更快；记录首次初始化与稳态 CPU/GPU、同步等待与显存。同画质比较后决定优化，不能通过删功能或降低采样冒充收益。

现有 HDR／DOF 空间等画面语义问题不夹带在后端等价迁移里；先保留明确基线，有意改变画面再单独验收。Inspector 的 Pass 快照和 HDR 链重整后续接在实际资源边界上，避免建设另一套过渡捕获系统。

本轮仅源码审查与方案归档，未改引擎、未构建、未运行 GPU。历史测试结果不代替以上验收。
