# Frame Inspector 演进方案

状态：**讨论提案，未实现，不含实现授权**。基线14a6b0d，2026-11-18。对应[讨论](../conversations/2026-11-18-pass-graph-rhi-inspector.md)。

## 当前问题与准确边界

RenderDiagnostics.inl的copyFrameCapture在FrameCapture阶段复制当前资源，保存Frame ID、Pass/Draw元数据和最终捕获点图像；当前导出JSON只有元数据。点事件行没有重新执行GPU，也没有该事件专属图像。选择Draw20时看到同一最终颜色，不能称为Draw20完成后的颜色。

每个Draw的历史画面必须在当时留快照，或从保存的初始状态和命令重新执行获得。下一帧重新渲染可供诊断但不是过去那一帧的原始历史。Render Graph可提供插桩位置，不能事后还原已被覆盖的纹理。

## 建议里程碑

| 阶段 | 产出 | 可回答的问题 | 验收 |
|---|---|---|---|
| M1 Pass快照 | 按需捕获Shadow/GBuffer/Lighting/DOF/Outline边界，记录Frame/View/Pass/资源版本/格式/子资源与实际执行状态；支持前后/差分 | 错误最早在哪个阶段出现 | 每个图像确属相应边界；后续覆盖/resize/preview/GC不改变；失败保留旧捕获 |
| M2 离线捕获包 | 版本化清单+实际纹理/缓冲载荷+必要有效常量与Shader身份+校验/预算；离线资源浏览 | 关闭引擎或换机器仍能看捕获内容吗 | 无原工程也能浏览；格式/截断/超预算错误可恢复；只含快照不冒称可回放 |
| M3 指定Draw检查 | 用户先选择下一次捕获的Pass/Draw范围，捕获该命令前后颜色/深度和绑定快照，显示Actor/材质/Shader/深度/剔除/viewport状态 | 这个Draw是否改变输出，使用了什么参数 | 精确event/frame身份、前后对照；零Draw/剔除/未执行明确报告；新帧结果不冒充旧帧 |
| M4 受限回放 | 先仅静态D3D11光栅场景，保存初始资源、必要Shader字节码/状态、Draw/清屏/拷贝/更新命令与顺序；在隔离目标重放到事件N | 从同一捕获重新执行到第N个事件 | 原始与回放一致性比较；资源创建/覆盖/删除/热编译版本可重建；不碰Live工程和GI历史 |
| M5 像素历史/更广回放 | 在受限回放稳定后做像素候选事件筛选、depth/stencil/discard/blend原因，再评估计算/DXR/跨API/多帧历史 | 哪次操作如何改变这个像素，为什么失败 | 限定支持的操作；不能从单纯前后图像断言深度失败原因；复杂写入单独验证 |

顺序M1→M2→M3→M4是建议，不是冻结排期。M1/M2和M3不依赖完成RHI；先用现有执行器的明确边界接入即可。M4长期应借助统一命令/资源描述减少漏记，但实现RHI本身不会自动获得回放。

## 预算与副作用

- 不默认每个Draw全尺寸复制所有附件。1920×1080 RGBA8一张约7.9MiB，100份就约791MiB，还未计Depth/GBuffer/HDR；当前常驻捕获预算256MiB无法承载无界事件历史。
- 默认捕获一帧、少量选定Pass/资源；用户可选Draw范围、区域/分辨率或元数据模式。降分辨率图必须标注，不能用于原分辨率精确像素历史。预算拒绝与不完整状态需可观察，不静默丢附件。
- GPU副本在同帧正确命令顺序插入；CPU读回和写盘按需/异步分批，设置上限。捕获本身会增加复制、同步和内存开销，统计要标记受捕获影响。
- 原始数据、显示转换和缩略图分开；Frame/View/Pass/Event/资源版本可追溯。主场景捕获不能被材质球、相机预览消费。替换旧SRV需在UI安全边界退役。
- Progressive或Realtime依赖此前HDR历史、采样序号、随机种子和加速结构输入；只保存当前相机和材质不足以重放。DXR混合路径还需描述两API队列及共享资源/同步依赖，不能简单复制一串Draw。
- 导出走用户明确选择的位置，不自动写入项目Content或提交大文件；捕获失败保留上一次有效快照。

## 当前推荐首个切片

先实现“选一个Pass → 捕获前后SceneColor/Depth或该Pass附件 → 并排与差分查看”，串通事件身份与资源版本。这样可以立即定位景深/光照/描边在哪一步出错，比直接建设全API回放更贴近现有工作流；但用户尚未授权实现。
