# 渲染与渲染诊断近期收敛方案（2026-11-18）

状态：**优先级建议，尚未实施**。用户明确近期偏好为优化渲染及RenderDoc式调试，不继续同时铺开多个板块。引擎基线14a6b0d。
关联：[Inspector长期方案](FrameInspectorEvolution.md)、[讨论](../conversations/2026-11-18-rendering-diagnostics-focus.md)。

## 主线

先看得清每个阶段 → 整理线性HDR成图边界 → 用测量和对照图优化具体热点。近期不把完整RHI/多后端/节点材质/NPR/完整自研命令回放列为前置任务；这些并未取消。

RenderDoc是外部专业GPU调试器；本引擎内置工具继续名为Frame Inspector，侧重Actor/材质/Pass身份和前后差异。两者互补，不把内置工具扩张为完整RenderDoc复制。外部先验证关闭DXR的D3D11最小案例，设备/资源/Pass设置可读；当前混合DX11/DX12-DXR共享路径需独立验证，不能据工具支持D3D12就声称该组合可捕获。

## 第一个可验收任务：Pass前后捕获与对照

用户行为：选择Lighting或DOF等实际执行阶段，Capture next frame，明确看到该阶段输入/执行前与执行后资源，进行并排/差分与原始像素检查。

- 默认单主视图、D3D11光栅最小场景；先做DOF/Outline的颜色前后，再接GBuffer/Lighting/Shadow实际附件。阶段以小提交递进，不一口气捕获所有资源。关闭的Pass明确“未执行”，不显示上一帧伪结果。
- Frame/View/Pass/Event/资源及子资源身份明确，颜色/深度格式、HDR还是显示颜色、原始值与预览转换分开。Pass菜单来自实际执行边界，不维护另一套手写名称。
- 请求才复制，配置资源范围/预算；默认不逐Draw保存全屏附件。失败保留旧快照，超预算可观察，resize/Shader/GC/工具预览后仍冻结，UI借用纹理安全退役。
- 保持本轮CPU提交、GPU计时和捕获复制开销区分；现有D3D11计时不冒称DXR全通道GPU耗时。缺测量范围应显示未测。
- 验收：同帧DOF开关/焦点及outline前后与实际GPU输出一致；主视图/预览隔离；临时工程回归；正常不捕获时无额外纹理复制/读回；捕获资源预算及失败恢复验证。

## 第二个任务：统一HDR与显示转换职责

目标成图：直接光+间接HDR → HDR颜色效果（适用阶段，如景深/Bloom）→ 曝光/色调映射/显示编码 → 编辑器叠加。每种效果的空间明确，不能断言所有后处理都必须在色调映射前。

- 从D3D11 Forward/Deferred提取DisplayColor职责，明确线性HDR SceneColor与显示目标，调试数据视图不误做美术转换。
- 使用第一阶段工具查看HDR原始值/显示预览和ToneMap前后；关闭新效果时与基线保持约定误差。
- Realtime继续合成间接HDR再显示；Progressive已有自己的HDR均值/resolve，显示转换需只发生一次。只迁移光栅第一切片时必须标注PT尚未统一，不能把RGBA8共享颜色当原始HDR。
- 独立保留编辑器描边/UI在显示侧。修改DOF空间会改变画面，不把有意变化藏入无行为重构；分开基线和新效果验收。
- HDR链稳定后再选择一个新效果（如Bloom）验证扩展，避免同时加入多个效果而无法定位回归。

## 第三个任务：基于证据优化热点

用简单PBR、多灯/深度场景、大量重复静态网格三个固定夹具，固定相机/分辨率/GI预算，分别记录首次准备与稳态CPU/GPU、显存、Draw/三角与捕获开销。R8用户资产不是公开唯一基准。

按测量决定世界三角重展/AS更新、共享fence等待、全屏Pass与DOF采样、局部光阴影等优先级；每轮只改一个热点并保留画面对照。不能提前承诺提高FPS或以降采样冒充等画质优化。实时GI降噪和TLAS优化是候选，不是全部同时开工。

## 阶段关系与暂缓项

Inspector长期方案M2离线包/M3 Draw检查仍保留；本次跨模块优先顺序改为“Inspector最小Pass对照 → HDR链 → 测量选热点”，不必先完成全部Inspector里程碑才做渲染。完整RenderGraph/RHI和通用回放只在出现明确阻碍时做必要切片。

外部参考：[RenderDoc官方README](https://github.com/baldurk/renderdoc/blob/v1.x/README.md)列出API范围；支持某API不等于本项目混合通道已验收。未运行外部RenderDoc，未新增渲染实现。
