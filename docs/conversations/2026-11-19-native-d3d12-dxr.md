# 纯 D3D12 能否开启硬件光追？

日期：2026-11-19
状态：分析完成，实现方案待选择

## 问题

后端下拉里有：

- `D3D11 + D3D12 ray tracing`（混合）
- `Auto`
- `D3D11 (strict)`
- `D3D12 (experimental raster)`

用户问：使用纯 D3D12 时不能开光追吗？

## 结论

当前构建里**不能**。这不是 DXR 的 API 限制——DXR 本身就是 D3D12 API；限制在引擎接线：原生 D3D12 后端只接通了光栅，DXR 只存在于 D3D11/D3D12 混合 bridge 中。

## 证据

- `docs/RenderBackends.md`：三种执行方式中，硬件光追与 GI 仅混合模式可用；原生 DXR 尚未接入。
- `src/Renderer/RenderFeatures.cpp` 对原生 D3D12 明确报告：
  - `Native D3D12 hardware ray tracing is not implemented in this build; the request is retained.`
  - 或 `Native D3D12 hardware ray tracing is not implemented; the D3D11/DXR bridge is unavailable to this backend.`
- 原生 D3D12 RHI（`src/Renderer/D3D12/D3D12Rhi.cpp`）用 `D3D12CreateDevice(..., ID3D12Device)` 创建基础设备，命令路径未使用 `ID3D12Device5`／`ID3D12GraphicsCommandList4`，没有 RTPSO/SBT/TLAS 绑定与 `DispatchRays`。
- 现有硬件光追模块 `src/Renderer/D3D12/HardwareRayTracing.h` 是显式 DX11↔DX12 bridge：
  - `initialize(ID3D11Device*, ID3D11DeviceContext*, ...)`；
  - `output()` 返回 `ID3D11Texture2D*`，`indirectLighting()` 返回 `ID3D11ShaderResourceView*`；
  - 内部自己 `D3D12CreateDevice(..., ID3D12Device5)`，通过 shared texture + shared fence 与 D3D11 互操作，再把结果交给 D3D11 光栅合成。
- 所以纯 D3D12 运行时没有这套 D3D11 设备／共享纹理路径，请求被保留但 Feature 显示不可用。

## 如果要做原生 D3D12 DXR

可行，分阶段：

1. **RHI 基础**：native12 设备 QueryInterface `ID3D12Device5`，命令上下文支持 `ID3D12GraphicsCommandList4`；DXR scene（BLAS/TLAS）与材质 buffer 复用现有 `HardwareRayTracing` 的场景构建代码，但改用 native 资源/命令/围栏。
2. **最小切片：硬件阴影**：RTPSO + SBT（raygen/miss/closest-hit/any-hit），输出可见度纹理，在 native 光照 Pass 合成；先不做反射/GI，风险最低。
3. **反射/GI**：把现有 DXR 反射、realtime GI、progressive GI 的采样与历史迁到 native 纹理和 Pass；处理 UI 借用纹理、诊断/捕获。
4. **收尾**：RenderFeatures 的 native 能力／原因、后端选择说明、`--native-d3d12-self-test` 的 DXR 用例、混合 bridge 继续留给 D3D11 主渲染用户。

工作量是多天的专项，不是加一个开关；风险集中在 descriptor/heap 绑定、资源状态/围栏、RTPSO 编译与 shared history 生命周期。

## 当前建议

- 现在要用硬件光追／GI：切 `D3D11 + D3D12 ray tracing`。
- 想让实验性纯 D3D12 完整：先做阶段 2（硬件阴影），验证 native DXR 基础后再迁反射/GI。

## 待选择

- A：先补原生 D3D12 硬件阴影最小切片；
- B：一次性补完整原生 DXR（阴影＋反射＋GI）；
- C：暂不开发，继续用混合后端。

## 实施结果（2026-11-19，补充模型）

用户选择 B，已完成：`HardwareRayTracing` 增加 native 模式，复用光栅 `ID3D12Device5`/queue，输出普通 D3D12 UAV 图像；RHI 新增 `importTexture`，native 管线增加 HardwareTransport/HardwareResolve，硬件图像复制回场景色，Realtime GI 间接光复制到 RHI 纹理后由光照采样。旧 D3D11/D3D12 共享 bridge 完全保留。

验证：native self-test 报告 DXR active（硬件预览 + Realtime GI 4/8 samples），Sandbox native DXR 5 帧 validation 0，Realtime GI 12 帧、Progressive GI 64 samples 均 validation 0；混合 hardware-rt self-test、editor self-test、AA self-test 通过；CTest 30/30。提交 `c017ff8` 已推送。

边界：仍是“DXR 整幅硬件预览替换光栅”语义；DOF/Outline/解析光追、运动重投影、DispatchRays/SBT 尚未迁移 native。详见 [任务 v1](../tasks/2026-11-19-native-dxr/v1.md) 与 [经验](../experience/NativeDxr.md)。
